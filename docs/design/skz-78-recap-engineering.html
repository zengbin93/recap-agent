SKZ-78 RecapAgent 工程化设计

目标：把复盘系统拆成可由大模型独立调用的技能单元，并让 GitHub Actions 每天北京时间 08:00 自动编排复盘、生成报告、推送飞书卡片。

Skill 边界

Skill职责不负责
recap-data-collectTushare 调用、重试、缓存、降级、manifest 输出。不复制金融数据知识，表口径交给已有 tushare skill / Tushare 能力。
recap-daily日复盘 HTML 与飞书卡片。不处理周/月复盘策略。
recap-weekly周复盘 HTML 与飞书卡片。不处理日/月复盘策略。
recap-monthly月复盘 HTML 与飞书卡片。不处理日/周复盘策略。
feishu-card-pushwebhook 解析、签名、dry run、发送。不生成复盘内容。

数据流

  1. Claude Code action 读取 task 参数并调用 scripts/run_recap.py。
  2. runner 使用 recap-data-collect 拉取数据；Tushare 失败时先重试，再读缓存，最后读 fallback fixture。
  3. 任务 skill 渲染 HTML 和飞书 interactive card JSON。
  4. feishu-card-push 按任务专用、多群 JSON、默认 webhook 的顺序解析目标并发送。
  5. workflow 总是上传 artifact，失败时保留报告、缓存和卡片 payload。

Secrets

必需：TUSHARE_TOKEN、ANTHROPIC_API_KEY。飞书可用默认单群 webhook，也可用任务专用变量或 FEISHU_WEBHOOKS_JSON 配置多群。

验证策略

单元测试覆盖数据采集重试/缓存/降级、飞书配置解析/签名/发送、报告 HTML/card 渲染、workflow cron/secrets/artifact/失败可见性。workflow 通过 dry run 支持人工复验。
