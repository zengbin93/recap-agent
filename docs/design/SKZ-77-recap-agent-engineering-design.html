Issue SKZ-77 RecapAgent 全球市场复盘 设计方案

复盘任务 Skill 化、定时编排与飞书卡片推送设计

本文档记录从零搭建复盘工程体系的设计方案。当前仓库只包含基础 README、LICENSE 和 gitignore，因此本方案按新项目组织，而不是按存量重构处理。

1. 目标与边界

目标是把全球市场复盘建设成一套由 Claude Code 驱动、按日定时运行、按任务拆分 skill、并通过飞书卡片分发结果的工程化系统。

  • 每个复盘任务是一个独立 skill，聚焦单一问题：日复盘、周复盘、月复盘。
  • 共享数据采集能力独立成 skill，但只做复盘工程内的数据契约、缓存和质量检查。
  • 已有 tushare skill 作为数据研究和接口选择能力复用，不在仓库内重造。
  • GitHub Actions 每天北京时间 08:00 触发，由 Claude Code 编排全量复盘任务。
  • 每个复盘任务生成自己的飞书卡片，通过 GitHub Secrets 中的飞书机器人 key 推送。

本阶段只落设计文档。实现阶段需另起 git worktree，先写 TDD，再实现代码、CI 和推送能力。

2. 推荐架构

推荐采用“项目级 Claude skills + 共享 Python 工具层 + GitHub Actions 调用 Claude Code”的结构。 skill 负责把复盘任务表达清楚，Python 工具层负责可测试、可复用、确定性的工程能力。

设计取舍

  • 选择多 skill：日、周、月复盘的判断口径不同，拆开能降低上下文污染， 也便于后续单独迭代和调度。
  • 保留共享工具层：飞书发送、HTML 渲染、数据 schema、缓存不应散落在 skill 文本里，应该落在可测试代码中。
  • 不重写 tushare skill：项目内只做复盘工程封装，避免复制已有自然语言数据研究能力。

3. Skill 拆分清单

Skill 职责 输入 输出 复用边界
market-data-collector 共享数据采集、标准化、缓存和质量检查。 task_type、as_of_date、时间范围、市场范围、数据集清单、输出目录。 标准化 JSON/CSV/parquet、manifest.json、数据质量告警。 复用已有 tushare skill 的接口选择与数据口径；不生成观点、HTML 或飞书卡片。
daily-market-recap 每日市场复盘，回答最近一个交易日发生了什么。 交易日、市场范围、数据目录、推送目标。 日报 HTML、日报卡片 JSON、短 Markdown 摘要。 只处理日频视角，不承担周/月趋势归因。
weekly-market-recap 周度市场复盘，回答本周主线如何演化。 周区间、最近 5 个交易日数据、主题配置、推送目标。 周报 HTML、周报卡片 JSON、主题/行业/风格变化摘要。 只做周度归纳，不替代每日异动追踪。
monthly-market-recap 月度市场复盘，回答本月市场结构、宏观和资金风格如何变化。 自然月或指定月区间、指数/行业/月度宏观数据、推送目标。 月报 HTML、月报卡片 JSON、结构性变化摘要。 只做月度结构判断，不承担日内或单周热点解释。

4. 数据流

  1. GitHub Actions 在北京时间 08:00 触发，或由人工使用 workflow_dispatch 手动触发。
  2. Claude Code 读取配置和日期参数，先调用 market-data-collector 建立本次复盘数据包。
  3. 日复盘每次执行；周复盘按配置在周末或周一执行；月复盘按配置在月末或下月首个交易日执行。
  4. 各复盘 skill 读取共享数据包，生成 HTML 报告、卡片 JSON 和摘要。
  5. 飞书发送层读取对应 secret，把每个任务的卡片发到目标群。
  6. GitHub Actions 上传 reports/ 与 artifacts/，用于审计和排查。

5. GitHub Actions 定时编排

工作流文件为 .github/workflows/daily-recap.yml。定时表达式使用 UTC 时间： 0 0 * * *，对应北京时间每天 08:00。 

on:
  schedule:
    - cron: "0 0 * * *"
  workflow_dispatch:
    inputs:
      as_of_date:
        required: false
      task:
        required: false
        default: all
      dry_run:
        required: false
        default: "false"

Job 设计：

  • checkout 仓库。
  • 安装 Python 依赖和项目包。
  • 准备 Claude Code 运行环境与项目级 skills。
  • 调用 anthropics/claude-code-action@v1，通过 prompt 要求 Claude Code 顺序编排复盘任务。
  • 上传 HTML 报告和中间产物。
  • 失败时生成 failure card，并在非 dry run 模式下推送飞书。

工作流应配置 concurrency，避免定时任务重叠；同时设置超时，防止数据源或模型调用异常导致任务挂起。

6. 飞书卡片推送

卡片生成和发送分离。每个复盘 skill 只产出自己的卡片 JSON；统一发送层负责读取 secret、构造 webhook URL、 签名和异常处理。

  • 默认 webhook：https://open.feishu.cn/open-apis/bot/v2/hook/{FEISHU_KEY}。
  • 多群扩展：优先读取 FEISHU_KEY_DAILY、FEISHU_KEY_WEEKLY、FEISHU_KEY_MONTHLY。
  • 回退规则：任务专用 key 不存在时回退到 FEISHU_KEY。
  • 签名规则：如果配置 FEISHU_SIGN_SECRET，发送层统一添加 timestamp/sign。
  • 卡片内容：标题、日期范围、3-5 条核心结论、热点主题、风险提示、报告链接或 artifact 信息。

7. Secrets 清单与 README 落点

Secret 必需性 用途 README 说明位置
TUSHARE_TOKEN 必需 Tushare 数据认证，供已有 tushare skill 和 Python tushare 包使用。 Configuration / Data source
FEISHU_KEY 必需 默认飞书群机器人 key。 Configuration / Feishu bot
ANTHROPIC_API_KEY 必需 GitHub Actions 中运行 Claude Code。 Configuration / Claude Code
FEISHU_KEY_DAILY 可选 日报专用群机器人 key。 Configuration / Feishu bot
FEISHU_KEY_WEEKLY 可选 周报专用群机器人 key。 Configuration / Feishu bot
FEISHU_KEY_MONTHLY 可选 月报专用群机器人 key。 Configuration / Feishu bot
FEISHU_SIGN_SECRET 可选 飞书机器人启用签名校验时使用。 Configuration / Feishu bot
REPORT_BASE_URL 可选 HTML 报告发布到 Pages 或对象存储时，用于生成卡片链接。 Configuration / Report hosting

README 应新增 Configuration、Operations、Local dry run 三个章节，并提供 .env.example，只列变量名和说明，不提交真实密钥。

8. 测试与验收策略

  • 数据契约测试：验证 manifest.json、标准化行情数据和质量告警字段。
  • 卡片 payload 测试：验证日/周/月卡片包含必需字段，且不泄露 secret。
  • 飞书发送测试：验证 webhook URL 拼接、任务专用 key 回退、签名逻辑和 dry run 行为。
  • HTML 渲染测试：验证报告文件可生成、标题和核心段落存在。
  • Workflow 静态校验：验证 cron、手动输入、必需 secrets 和 artifact 上传步骤存在。

实现阶段应先写失败测试，再用最小实现让测试通过。此文档只定义设计，不替代后续 TDD 过程。

9. 后续实施顺序

  1. 细节审核通过后，由终审确认方案。
  2. 终审通过后创建独立实现 worktree。
  3. 补齐项目骨架、公共 Python 工具层和测试框架。
  4. 按 TDD 顺序实现数据契约、卡片生成、飞书发送、HTML 渲染。
  5. 新增 Claude skills 和 GitHub Actions workflow。
  6. 更新 README 与 .env.example。
  7. 在 docs/development/ 记录带 issue 信息的开发过程 HTML。
  8. 验证通过后提交 PR，等待人工或其他智能体验收。
