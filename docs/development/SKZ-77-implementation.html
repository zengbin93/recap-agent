1. 交付概述

按定稿设计落地复盘工程：5 个 Claude Code 项目级 skill + 可测试 Python 工具层 + GitHub Actions 每日 08:00（北京）编排 + 飞书卡片推送。 工具层零运行时依赖（urllib / unittest / hmac 等 stdlib）；tushare / pandas 仅在数据采集时按需 import，单测在边界 mock，因此 CI 单测无需安装它们。

覆盖的非 happy-path：daily 缺失 / 无 key 抛错、weekly/monthly 回退 daily、weekly 无 key 也回退、JSON 解析失败、顶层非对象、签名已知向量（timestamp=1700000000, secret="abc"）、空/损坏/截断缓存丢弃、限流 3 次后 SkipDataset、不可重试错误立即抛、workflow 静态校验（cron / secrets / continue-on-error / artifact / claude-code-action）。

4. 关键决策与取舍

4.1 FEISHU_WEBHOOKS 单 JSON（覆盖设计文档的 FEISHU_KEY*）

偏离设计文档。

设计文档原用 FEISHU_KEY + FEISHU_KEY_{DAILY,WEEKLY,MONTHLY} 多个 secret 加回退规则；验收人在审核要点里明确改为单个 FEISHU_WEBHOOKS JSON（daily 必填、weekly/monthly 缺省回退 daily）。本实现以验收人最新指令为准，更紧凑（一个 secret 搞定），签名也内化到每个任务对象的 sign_secret 字段。

4.2 零运行时依赖（stdlib 优先）

环境为干净的 Python 3.14。HTTP 用 urllib、测试用 unittest、签名用 hmac/hashlib/base64。tushare/pandas 在 _default_fetcher 内按需 import，对外只吐 list[dict]，单测在 fetcher 边界注入 fake，因此 pip install -e . 即可跑全部 54 个测试。

4.3 flat layout

包源码放在仓库根的 recap_agent/（而非 src/recap_agent/），让 python -m unittest discover -s tests 零配置即可 import，CI 少一步。

4.4 失败可见性落到 CI 层面

workflow 的 daily / weekly / monthly 三个 anthropics/claude-code-action step 各自 continue-on-error: true，单个任务失败不阻断同批其它任务；末尾 if: always() 上传 artifact 并把每个任务的 outcome 写入 Step Summary。

4.5 workflow 注入面

workflow_dispatch 的 task / as_of_date 输入经 env: 中转进 run:，而非直接 ${{ }} 插值；--task 并由 argparse choices 校验，收敛注入面。
