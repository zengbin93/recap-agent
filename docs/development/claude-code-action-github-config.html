在 GitHub Actions 中配置 Claude

本文档汇总 anthropics/claude-code-action@v1 的配置方法，覆盖：可配置项总览、官方 Anthropic 接入、GLM 等 Anthropic 兼容模型接入、以及定时任务（cron）三种落地场景。

1. 可配置项总览

v1 把 v0.x 一堆分散输入合并为 prompt + claude_args 两个核心入口，并按是否填写 prompt 自动判定模式：留空走 Tag 模式（响应评论里的 @claude），填写走 Agent 模式（自动化任务）。

核心 with 输入

参数说明默认
prompt给 Claude 的指令。留空=Tag 模式；填写=Agent 模式。空
claude_args直接透传给 Claude CLI 的参数（见下）。取代 v0.x 的 max_turns/allowed_tools/model 等。空
track_progress设 true 强制 Tag 模式并生成进度追踪评论，自动注入 PR/Issue 上下文。仅对特定 PR/Issue 事件生效，用错事件会报错。false
trigger_phrase触发关键词。@claude
assignee_triggerIssue 指派给某用户名时触发。空
label_trigger打上某标签时触发。空
base_branch新建分支的基础分支。仓库默认分支
branch_prefixClaude 创建分支的前缀。claude/
use_sticky_comment复用同一条评论更新，而非每次新建。false
use_commit_signing通过 GitHub API 提交并签名 commit。false
allowed_bots允许触发的 bot 用户名（逗号分隔，*=全部）。空
github_token自定义 GitHub token。自动生成
settingsClaude Code settings JSON 字符串或文件路径。空
path_to_claude_code_executable自定义 Claude Code 可执行文件路径。空

claude_args 常用透传项

参数说明
--model指定模型（如 claude-sonnet-5、opus）。
--max-turns最大对话轮数。
--system-prompt / --append-system-prompt覆盖 / 追加系统提示。
--allowedTools / --disallowedTools工具白名单 / 黑名单。
--mcp-configMCP 服务器配置。
--json-schema让 Claude 输出结构化 JSON，自动成为 Action output 供后续步骤使用。
--fallback-model主模型不可用时的降级模型。

超时不再是 Action 输入，改用 job 级 timeout-minutes。

2. 认证配置（三选一）

方式配置
Anthropic API 直连anthropic_api_key: ${{ secrets.ANTHROPIC_API_KEY }}
OAuth（Pro/Max 订阅）claude_code_oauth_token: ${{ secrets.CLAUDE_CODE_OAUTH_TOKEN }}
Bedrock / Vertex（企业云）环境变量 CLAUDE_CODE_USE_BEDROCK: "1" 或 CLAUDE_CODE_USE_VERTEX: "1"，配合 OIDC 免密

3. 接入 GLM 等 Anthropic 兼容模型

GLM 提供 Anthropic 兼容接口，不改 Action 本身，只通过环境变量把底层 Claude Code 指向智谱端点。

需要的 Secrets：仅一个 GLM_API_KEY（智谱开放平台申请的 API Key）。

- uses: anthropics/claude-code-action@v1
  env:
    ANTHROPIC_BASE_URL: https://open.bigmodel.cn/api/anthropic
    ANTHROPIC_AUTH_TOKEN: ${{ secrets.GLM_API_KEY }}
    ANTHROPIC_MODEL: glm-4.6              # 换成平台上的准确模型标识
    ANTHROPIC_SMALL_FAST_MODEL: glm-4.5-air   # 后台轻量调用用的小模型
  with:
    prompt: "审查这个 PR"
    claude_args: |
      --model glm-4.6

要点：

  • ANTHROPIC_BASE_URL 指向智谱 Anthropic 协议兼容地址。
  • 用 ANTHROPIC_AUTH_TOKEN 放 key，而非 anthropic_api_key 输入项。
  • 模型名在 ANTHROPIC_MODEL 与 --model 保持一致，去平台确认准确标识。
  • 指定 ANTHROPIC_SMALL_FAST_MODEL，避免后台轻量任务报错或浪费。
  • 不要同时传 anthropic_api_key / claude_code_oauth_token，会与 base URL 鉴权冲突。

4. 定时执行任务（cron）

定时任务用 GitHub 的 schedule（cron）触发，配合 Agent 模式（填 prompt）。

name: Claude 定时任务
on:
  schedule:
    - cron: "0 1 * * *"      # 每天 UTC 01:00（北京时间 09:00）
  workflow_dispatch:          # 手动触发，方便测试

jobs:
  scheduled-task:
    runs-on: ubuntu-latest
    timeout-minutes: 30
    permissions:
      contents: write         # 需改代码/提交时
      issues: write           # 需建 issue 时
      pull-requests: write    # 需开 PR 时
    steps:
      - uses: actions/checkout@v4
      - uses: anthropics/claude-code-action@v1
        with:
          anthropic_api_key: ${{ secrets.ANTHROPIC_API_KEY }}
          prompt: |
            汇总昨天合并的所有 commit 和新开的 issue，
            生成一份日报并创建成一个新的 GitHub issue。
          claude_args: |
            --model claude-sonnet-5
            --max-turns 15

要点：

  • cron 为 5 段式 UTC 时间，北京时间需减 8 小时。
  • 定时场景必须填 prompt（走 Agent 模式），否则无评论上下文。
  • permissions 按需授予：只读分析 contents: read；提交/开 PR 加 pull-requests: write；建 issue 加 issues: write。
  • GitHub schedule 有延迟（高峰可能推迟十几分钟），且只有默认分支上的 workflow 才会定时触发。
  • 若改用 GLM 跑定时任务：加上第 3 节的 env，去掉 anthropic_api_key 即可。

cron 常用写法

表达式含义
0 1 * * *每天一次
0 1 * * 1每周一
0 */6 * * *每 6 小时

场景需要的 Secret
